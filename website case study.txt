## Overview

RUN() is a remote code execution platform that lets users write and run programs in multiple languages directly from the browser.  
Instead of running code locally, execution happens inside isolated Docker containers to ensure safety and reproducibility.

## The Problem

Setting up local compilers and runtimes is friction-heavy for beginners and risky for shared machines.  
Running untrusted code directly on a host system is unsafe, yet most simple online editors rely on insecure execution or limited sandboxes.

RUN() solves this by separating the editor from the execution engine and running all code in disposable containers.

## Architecture

![Architecture diagram](/media/run-arch.png)

\`\`\`
Browser 
→ React Frontend 
  → Go Execution API 
    → Docker Runners
      → Isolated Containers
\`\`\`

Execution flow:

1. User writes code in the browser editor.
2. Frontend sends { language, code, stdin } to the Go API.
3. API creates a temp workspace and spins up a language-specific container.
4. Code runs with CPU/memory/network limits.
5. stdout and stderr are returned to the browser.

## Key Decisions

- **Why Go backend?** — Fast startup, strong concurrency model, perfect for process orchestration.
- **Why Docker isolation?** — Each execution runs in a disposable container, preventing host compromise.
- **Resource limits** — CPU, memory, and process caps prevent abuse and infinite loops.
- **Stateless API** — Frontend and backend can scale independently.

## Security Model

- No network access inside containers
- Non-root execution user
- Temporary filesystem per run
- Resource limits to prevent abuse
- Containers destroyed after execution
